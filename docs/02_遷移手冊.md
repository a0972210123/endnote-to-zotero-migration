# EndNote → Zotero 遷移手冊

> **這份手冊的由來**：台大醫圖終止 EndNote 校園授權，**2026/11/1 生效，資料備份截止 10/31**
> （[公告](https://ntuml.mc.ntu.edu.tw/News!one.action?nid=1391)）。到期後 EndNote 只顯示前 10 筆、
> 無法新增／編輯／匯出、Word 的 CWYW 失效。
>
> **不是台大的人也能用**：授權到期只是「為什麼現在要搬」，
> 底下的流程與時程無關——**任何要把 EndNote 搬到 Zotero 的情況都適用**。
> 沒有時間壓力的話，跳過各章的「10/31」提醒即可。
>
> **好消息**：文獻、PDF 附件、分組階層**可以完整搬過去**，本手冊的流程已在 2,257 筆、
> 366 個分組、1,952 個 PDF 的實庫上跑完並驗證。

> [!tip] 全程零風險
> 整個流程**不會修改你的 EndNote library**——所有步驟都是「從 EndNote 讀出來、寫進 Zotero」。
> 就算中途出錯，EndNote 原庫完好，重來即可。EndNote 也可以留著用到 11/1。

# 第 0 章　開始前先回答兩題

## 0-1　有沒有正在寫的 Word 稿？

**這題比搬文獻庫更急。** 11/1 之後 CWYW 失效，已插入的引用就**無法再重新格式化**——
換期刊格式、更新參考文獻清單、增刪引用全都做不到。

| 你的狀態 | 怎麼辦 |
|---|---|
| **11/1 前能定稿投出** | 繼續用 EndNote 寫完。文獻庫另外搬，兩件事不衝突 |
| **11/1 後還要改** | **授權到期前**必須處理，見下方二選一 |
| **還沒開始寫** | 直接用 Zotero 開始，別再用 EndNote 插引用 |

### 11/1 後還要改的人：二選一

| | **A. 轉成純文字（凍結）** | **B. 改用 Zotero 重插** |
|---|---|---|
| 花多久 | 幾分鐘 | 依引用數，數小時到數天 |
| 之後能做 | 手動編輯文字 | 自動換格式、增刪、更新 |
| 之後**不能**做 | ❌ 換格式、自動更新 | — |
| 適合 | 接近定稿、只剩小修 | 還要大改，或可能改投別家期刊 |

**選 A 的操作步驟：**

> 🔴 **先另存副本，並確認存好。這個動作不可逆。**

1. `檔案 → 另存新檔`，存成 `論文_含EndNote碼_日期.docx`（保留 EndNote 連結的救命備份）
2. Word 上方 **EndNote 分頁** → **Convert Citations and Bibliography** → **Convert to Plain Text**
3. 對話框說明「將產生不含 EndNote 欄位碼的新文件」→ 確認
4. **Word 開出一個新視窗**，那份才是純文字版；**原檔仍開著且未被修改**
5. 把新視窗那份另存為 `論文_純文字版_日期.docx`

**驗證**：點內文的引用，如果選不到「灰底欄位」而是普通文字 → 成功。

> 選單文字依 EndNote 版本略有不同，都在 Word 的 EndNote 分頁下。找不到就問，別亂點。

## 0-2　你走哪條路？

**這是能力分流，不是偏好分流。**

### 先確認四件事（30 秒，現在花的時間會省下好幾小時）

| # | 檢查 | 怎麼看 |
|---|---|---|
| 1 | **有 Python 3.8 以上？** | Windows 打 `python --version`；Mac 打 `python3 --version`（詳見第 4-0 章） |
| 2 | **EndNote 是 X9.3 以上？** | `Help → About`；或確認 `<library>.Data` 裡有 `sdb/sdb.eni` 這個檔案 |
| 3 | **Zotero 有 `Tools → Developer → Run JavaScript`？** | 打開 Zotero 的 Tools 選單看一眼 |
| 4 | **作業系統** | Windows 都測過了；**Mac 可以走，但指令略有不同**，見第 4-0 章的 Mac 對照表 |

**前三項全部 ✅ → 可走路徑 A。任何一項 ❌ → 走路徑 B。**

> 🔴 **第 2、3 項一定要現在看。**
> 它們不合格的話，你會一路順利做到**第 3 步或第 7 步才卡死**——
> 而那時可能已經匯入好幾千筆了，只能全部刪掉重來。
>
> ⚠️ **第 3 項沒有那個選單 = 你的 Zotero 太舊**，先更新到最新版就有了。

> 📌 **還有一關在第 1-1 章**：你的 library 如果放在 OneDrive／Dropbox 等雲端同步資料夾裡，
> **兩條路都要先處理**（EndNote 官方明言不相容，直接操作可能損毀）。
> 那一關要先找到 library 路徑才能檢查，所以排在第 1 章。

### 兩條路的差別

| 你的情況 | 走 |
|---|---|
| 上面四項全過 | **路徑 A** |
| 任何一項沒過，或不想碰程式 | **路徑 B** |

| | 路徑 A | 路徑 B |
|---|---|---|
| 匯出次數 | **1 次**（整庫） | **每個 Group 各 1 次** |
| 分組結果 | **兩層**（group set → group），與 EndNote 一致 | **單層**平鋪 |
| 跨組文獻 | 不重複匯入 | 會重複匯入，需事後合併 |
| 需要 | Python 3.8+ | 只要滑鼠 |

> **為什麼路徑 A 需要 Python？** 分組結構存在 EndNote 的 `sdb.eni`（一個 SQLite 資料庫）裡，
> Zotero 讀不到 EndNote 的檔案，只能用外部程式讀出來。這是技術限制，繞不過。

> **分組不多（少於 10 組）或根本沒用分組的人**：直接走路徑 B，不必為此裝 Python。

# 第 1 章　前置確認

## 1-1　找出「現役」library ⚠️ 最容易出錯的一步

**電腦上常常有好幾份 EndNote library**（舊備份、不同年份的副本、雲端同步下來的）。
分析錯一份，後面全部白做。

**判別方法：**

1. 開啟 EndNote，看視窗標題列顯示的檔名——**那就是現役的**
2. 或查最近開啟紀錄：Windows 登錄檔
   `HKCU\Software\ISI ResearchSoft\EndNote\Recent Libraries`
3. 比對各份 `<library>.Data\sdb\sdb.eni` 的**修改時間**，最新的通常是現役

**記下這兩個路徑**（後面一直要用）：

```
<你的library>.Data\sdb\sdb.eni     ← EndNote 資料庫
<你的library>.Data\                 ← 資料夾本身（底下有 PDF 子資料夾）
```

> 例：library 是 `D:\我的文獻\MyLibrary.enl`，
> 那 `.Data` 就是 `D:\我的文獻\MyLibrary.Data\`

### 🔴 順便確認：你的 library 是不是放在雲端同步資料夾裡？

**看剛才那個路徑，裡面有沒有出現這些字：**

`OneDrive`／`Dropbox`／`Google Drive`／`SharePoint`／`iCloud`／`雲端硬碟`

**如果有 → 先處理再往下做。**

> **為什麼**：EndNote 官方（Clarivate）明確表示**不相容於雲端同步服務**，
> 也不建議直接從這些位置開啟 library。技術原因是 EndNote 存檔時要依特定順序寫好幾個檔案，
> 只要其中一個正在被同步，就可能寫不進去而**造成 library 損毀**。
>
> ⚠️ **很多人不知道自己中招**：不少學校的 OneDrive 會自動接管「文件」資料夾，
> 而 EndNote 預設就把 library 存在文件資料夾裡——**所以請真的去看一下路徑**。

**怎麼處理（二選一）：**

| 做法 | 步驟 |
|---|---|
| **A. 複製到本機再操作**（推薦） | 把 `.enl` 和 `.Data` **整組**複製到非同步的位置（例如 `D:\遷移暫存\`），之後全程用這一份。原本那份不要動，等於自動有了備份 |
| B. 暫停同步 | 在 OneDrive／Dropbox 圖示上點「暫停同步」，做完再恢復 |

> 💡 **A 的額外好處**：整個遷移過程都在複本上進行，原始 library 完全不會被碰到。
> 遷移完成、確認 Zotero 一切正常之後，複本可以直接刪掉。

## 1-2　盤點規模

在 EndNote 裡記下：

- [ ] **總筆數**（點 All References 看左下角）
- [ ] **Group 清單與數量**（截圖或抄下來，之後核對用）
- [ ] `.Data` 資料夾大小（右鍵 → 內容）

> 這三個數字後面每一步都要拿來核對。**沒記就沒辦法確認搬完整了。**

### ⚠️ 你的 Zotero 是全新的，還是已經有東西了？

- [ ] **打開 Zotero，記下「My Library」目前有幾筆**

| 你的情況 | 影響 |
|---|---|
| **全新空的 Zotero**（0 筆） | 最單純。之後核對筆數直接對 EndNote 的數字即可 |
| **已經用一段時間了**（有既存文獻） | ⚠️ 兩件事要注意，見下 |

**Zotero 已有既存文獻的人，請注意：**

1. **核對筆數要用「差值」**
   匯入後的總數 ＝ 你原有的筆數 ＋ EndNote 匯過來的筆數。
   例：原有 300 筆，EndNote 有 2000 筆 → 匯入後應該是 **2300 筆**，不是 2000 筆。
   **後面每個「核對筆數」的步驟都記得加上你原有的數字。**

2. **分組重建可能會把你原有的文獻也拉進 EndNote 分組**
   第 7 章的腳本是**用標題比對**來配對的。如果你原本 Zotero 裡就有某篇論文，
   而 EndNote 裡也有同一篇，腳本會把**兩筆都**指派到對應的 EndNote 分組裡。
   → 這通常無害（本來就是同一篇），但**不是錯誤，不用緊張**。
   → 之後用 Zoplicate 合併重複時會自動處理掉（第 8 章）。

> **建議**：既有內容不多的話，最乾淨的做法是先在 Zotero 建一個新的 collection
> 當作「EndNote 匯入區」，匯入時勾「Place imported collections and items into new collection」，
> 這樣至少視覺上分得開。

# 第 3 章　儲存決策：附件放哪

Zotero 免費帳號給 **300MB 雲端空間**——書目資料很小夠用，**但 PDF 附件放不下**。

| 方案 | 費用 | 適合 |
|---|---|---|
| **書目同步＋附件留本機**（推薦起手） | 免費 | 只用一台電腦，或自己有 Google Drive/OneDrive 同步 |
| Zotero 付費儲存 | 2GB US$20/年、6GB US$60/年 | 要多裝置隨時取用 PDF |
| WebDAV | 看你用哪家 | 已有 NAS 或校方 WebDAV |

> **先選免費**。書目照樣上雲（換電腦不會掉），附件用 Google Drive 同步整個 Zotero 資料目錄
> 就能達到差不多的效果。不夠用再升級，隨時可改。

**Zotero 資料目錄在哪**：`Edit → Settings → Advanced → Files and Folders`
（預設在 `C:\Users\<你>\Zotero`；空間不夠可在此改到別的槽）

### 成功長什麼樣

會印出一段 JSON 加一行總計，像這樣（數字是實際跑過的一個庫，你的會不同）：

```
{
  "refs_total": 2257,
  "refs_active": 2257,
  "refs_trash": 0,
  "groups": 371,
  "custom_groups": 366,
  "groupsets": 30,
  "orphan_groups": 5
}
total group memberships: 4821
```

**怎麼讀這些數字：**

| 欄位 | 意思 | 對照 |
|---|---|---|
| `refs_total` | library 裡的文獻總數（含垃圾桶） | |
| **`refs_active`** | **實際會搬過去的筆數** | ← **與第 1-2 章記的總筆數核對** |
| `refs_trash` | 在 EndNote 垃圾桶裡的，不會搬 | |
| `groups` | 全部 group（含 smart group） | |
| **`custom_groups`** | **你手動建的 group，會被重建** | ← **與第 1-2 章記的 Group 數核對** |
| `groupsets` | Group Set（上層分類）數 | |
| `orphan_groups` | 不屬於任何 Group Set 的散裝 group | 會被放進「(未分組)」 |
| `total group memberships` | 分組指派總次數 | 比 `refs_active` 大是正常的（一篇可屬多組） |

同一層資料夾會多出一個 **`snapshot.json`**，那就是快照檔，**後面第 7 章還要用，不要刪**。

### 🚦 關卡：數字不對就停

- [ ] `refs_active` 與你在 EndNote 看到的總筆數相符
- [ ] `custom_groups` 與你記下的 Group 數相符

> ❌ **對不上 → 你抓到的是錯的 library**（電腦上有多份備份）。
> **回第 1-1 章重找，不要繼續往下做。** 這一步錯，後面全部白做。

### 出錯了？

| 訊息 | 原因 | 解法 |
|---|---|---|
| `python 不是內部或外部命令` | 沒裝或沒加 PATH | 回 4-0 ① 重裝，記得勾 Add to PATH |
| `can't open file ...export_endnote_groups.py` | 命令列不在腳本資料夾 | 回 4-0 ③ 用 `cd` 切過去 |
| `unable to open database file` | sdb.eni 路徑打錯 | 用 Shift+右鍵「複製路徑」重貼 |
| `database is locked` | EndNote 開著 | 關掉 EndNote 再跑 |
| 中文變成 `\u4e2d\u6587` 或亂碼 | 編碼沒設 | 回 4-0 ④ |
| `SyntaxError` 一堆 | Python 版本太舊 | 回 4-0 ① 更新到 3.8+ |

# 第 5 章　匯出 XML

## 🔴 兩條路都適用的鐵則

1. **格式選 XML**，不要選 RIS——RIS 不帶 PDF、不帶分組
2. **儲存位置必須在 `<library>.Data` 資料夾內**

> **為什麼位置這麼要緊**：XML 裡記的附件路徑是**相對於 `.Data` 資料夾**算的。
> 存到桌面或別的地方，Zotero 找不到 PDF ——結果是**書目全部匯進來了，但一個 PDF 都沒有**。
> 這是本流程最常見、也最讓人白做一輪的錯誤。

## 路徑 A：整庫一次匯出

1. EndNote → 左側點 **All References** → `Ctrl+A` 全選
2. `File → Export…`
3. **Save as type 選 XML**
4. **存到 `<library>.Data\` 裡**，例如 `MyLibrary.Data\export-all.xml`
5. Text Encoding 選 **Unicode (UTF-8)**（避免中文亂碼）

### 驗證匯出結果（路徑 A 必做）

**這一步是整個流程最重要的檢查點**——它會告訴你「PDF 到底能不能跟著過去」。
現在發現問題，比匯入 2000 筆之後才發現省太多時間了。

回到命令列（一樣要在腳本資料夾）：

```
python scripts\verify_export_xml.py "<XML 路徑>" snapshot.json "<.Data 資料夾路徑>"
```

實際的樣子：

```
python scripts\verify_export_xml.py "D:\我的文獻\MyLibrary.Data\export-all.xml" snapshot.json "D:\我的文獻\MyLibrary.Data"
```

> 三個參數依序是：**剛匯出的 XML**、**第 4 章產生的 snapshot.json**、**`.Data` 資料夾本身**。

**成功長這樣：**

```
records in XML: 2257
active refs in snapshot: 2257
records without rec-number: 0
rec-numbers matching snapshot ids: 2257
rec-numbers NOT in snapshot active ids: 0
snapshot active ids NOT in XML: 0
attachment links: 1952 total, internal-pdf resolved OK: 1952, missing: 0
```

**逐行怎麼讀：**

| 這行 | 應該是什麼 | 不對的話代表 |
|---|---|---|
| `records in XML` | ≈ `active refs in snapshot` | 匯出時沒有全選（要先點 All References 再 `Ctrl+A`） |
| `snapshot active ids NOT in XML` | **0** 或極小 | 有文獻沒被匯出 |
| `rec-numbers NOT in snapshot active ids` | 0 或極小 | XML 與 snapshot 不是同一個 library！ |
| **`missing`** | **必須是 0** | 🔴 **XML 存錯位置，PDF 會全部搬不過去** |

### 🚦 關卡：`missing` 不是 0 就停

如果 `missing` 大於 0，它會列出前 5 個找不到的檔案路徑，像這樣：

```
attachment links: 1952 total, internal-pdf resolved OK: 0, missing: 1952
  missing: D:\我的文獻\MyLibrary.Data\PDF\1234\Chen-2020.pdf
```

**這幾乎一定是 XML 存錯位置**（存到桌面、下載資料夾、或 `.Data` 的外面）。

**修法：**
1. 刪掉剛才那個 XML
2. 回 EndNote **重新匯出**，這次確認存到 `<library>.Data\` **裡面**
3. 重跑驗證，直到 `missing: 0`

> **不要抱著「先匯入看看」的心態往下走。** 匯入 2000 筆要跑很久，
> 發現 PDF 沒跟來還要全部刪掉重來——這一關擋住，是幫你省好幾個小時。

> 💡 `internal-pdf resolved OK` 的數字比你的 PDF 總數少一點是正常的
> （有些文獻沒附件，有些附件是網頁快照不是 PDF）。**關鍵是 `missing` 要 0。**

### 如果你看到 `attachment links: 0 total`

```
attachment links: 0 total, internal-pdf resolved OK: 0, missing: 0
```

**這代表你的 EndNote 裡沒有 PDF 附件——不是出錯。**

- 只用 EndNote 管書目、PDF 另外存資料夾的人，看到 0 是**正常的**
- `missing: 0` 依然成立（沒有附件，自然沒有找不到的附件）
- **可以直接往下走**

> 如果你明明記得有附件卻顯示 0，那才有問題：多半是匯出時沒有勾到附件，
> 或那些「附件」其實是 EndNote 的**檔案連結（linked file）**而不是內嵌的
> PDF——後者不會跟著 XML 走，需要另外手動處理。

4. 下一個 Group，重複

> 跨組的文獻會被匯出好幾次——正常，第 8 章會合併掉，合併後 collection 取聯集，分組不會掉。

# 第 7 章　分組重建〔路徑 A 專屬〕

> **匯入後分組不見了是正常的**——Zotero 匯入 EndNote XML 不會帶分組結構，靠這一章補回來。
> 路徑 B 的分組已經在匯入時建好了（單層），跳到第 8 章。

**這一章分兩半**：先用 Python 算出「哪篇該進哪一組」（7-1），
再在 Zotero 裡執行實際建立（7-2）。

## 7-1　產生重建計畫

### ① 找出 Zotero 資料目錄

Zotero → `Edit → Settings → Advanced` → 找到 **Files and Folders** →
**Data Directory Location** 底下顯示的那個路徑就是。

常見位置是 `C:\Users\你的名字\Zotero`。**點旁邊的「Show Data Directory」會直接開啟該資料夾**，
裡面應該有一個 `zotero.sqlite` 檔案——那就是要餵給腳本的。

### ② 🔴 關掉 Zotero

**這步不能省。** 腳本用 `immutable=1` 模式讀 `zotero.sqlite`，
這個模式等於告訴資料庫「這檔案在我讀的時候不會變動」。
Zotero 開著同時在寫入，讀到的就會是半舊半新的資料，算出來的分組會錯。

**順序是**：匯入完成 → **關掉 Zotero** → 跑 7-1 → **重新開啟 Zotero** → 做 7-2。

### ③ 跑腳本

```
python scripts\build_collection_plan.py snapshot.json "<zotero.sqlite 路徑>" plan.json
```

實際的樣子：

```
python scripts\build_collection_plan.py snapshot.json "C:\Users\你的名字\Zotero\zotero.sqlite" plan.json
```

> 想改最上層資料夾的名字（預設叫 `EndNote分組`），加第四個參數：
> `python scripts\build_collection_plan.py snapshot.json "...\zotero.sqlite" plan.json "我的舊分組"`

**成功長這樣：**

```
sets: 30  groups: 366  assignments: 4795
unmatched refs (in no collection): 12
  [1187] Chen (2020) Effects of task-oriented training on upper limb
  [1443] 王小明 (2019) 職能治療介入對於...
```

**怎麼讀：**

| 這行 | 意思 | 要對照 |
|---|---|---|
| `sets` | 會建立的上層資料夾數 | 第 4 章的 `groupsets`（+1 是正常的，多一個「(未分組)」） |
| `groups` | 會建立的分組數 | 第 4 章的 `custom_groups` |
| `assignments` | 總共會做幾次「把某篇放進某組」 | 第 4 章的 `total group memberships` |
| `unmatched refs` | **在 Zotero 找不到對應的文獻** | 見下 |

### 🚦 關卡：unmatched 數量

| unmatched 數量 | 判讀 | 怎麼辦 |
|---|---|---|
| **0 到個位數** | ✅ 正常 | 那幾筆通常是標題有特殊符號比對不到，事後手動拖進分組即可 |
| **幾十筆** | ⚠️ 可接受但要看 | 看列出的標題有沒有共通點（例如都是中文、都是某年份） |
| **上百筆或大量** | ❌ 匯入不完整 | **回第 6 章**確認是不是有 XML 沒匯到 |

> 腳本是用**標題比對**（年份當同名時的判別依據）。所以 EndNote 裡標題留白、
> 或標題被 EndNote 存成奇怪格式的那幾筆，比對不到是正常的。

同層會多出一個 **`plan.json`**，7-2 要用。

## 7-2　在 Zotero 執行重建

### ① 改腳本裡的那一行路徑

用**記事本**（或任何文字編輯器）開啟 `scripts\rebuild_collections.js`。

> 💡 在檔案上按右鍵 → 「開啟檔案」→ 選記事本。**不要用 Word 開**。

找到最上面附近這一行（有明顯註解標示）：

# 附錄 A　常見錯誤排除

| 症狀 | 原因 | 解法 |
|---|---|---|
| 書目都在但 **PDF 全沒跟來** | XML 沒存在 `.Data` 資料夾內 | 刪掉該批匯入，把 XML 移進 `.Data` 重新匯入 |
| 匯入後**分組全不見** | 正常，Zotero 匯入不帶分組 | 路徑 A 見第 7 章；路徑 B 要逐 Group 匯出 |
| 匯入**極慢／卡死** | 一次太多 ＋ sync 開著 | 關 sync、分批（附錄 B） |
| 多出一堆**奇怪的 note** | EndNote 不支援欄位被塞成 note | 第 8-2 章 |
| **中文書目亂碼** | 匯出編碼不對 | 重新匯出，Text Encoding 選 Unicode (UTF-8) |
| 跑腳本**印中文報錯** | Windows 命令列預設 cp950 | 加 `PYTHONIOENCODING=utf-8` |
| Run JavaScript **報錯** | 沒勾「Run as async function」 | 勾起來再跑 |
| 腳本數字**跟 EndNote 對不上** | 抓到舊備份 library | 回第 1-1 章 |
| Word 沒有 Zotero 分頁 | 外掛沒裝上 | Zotero → Settings → Cite → 重裝 Word 外掛 |

# 附錄 B　大庫特別注意（超過 3,000 筆或 5GB）

- **一定要分批匯入**：每批 500–1000 筆。在 EndNote 用年份範圍或作者字母分段選取後分次匯出。
- **空間**：`.Data` 大小 × 2 只是最低標；轉檔過程另需暫存空間，建議留 × 2.5。
- **時間**：匯入單批數分鐘，全程可能數小時。**排在不用電腦的時段跑**（例如睡前）。
- **Google Drive 首次上傳**：數 GB 要好幾小時到一整天。提早開始，別排在 10/30。
- **Zotero 效能**：匯入完務必做第 8-2 章清 note，殘留 note 對大庫的效能影響很明顯。
- **建議**：大庫的人**優先走路徑 A**——逐 Group 匯出幾百次不現實，而且跨組重複匯入會讓庫再膨脹一輪。

# 附錄 D　用 AI 輔助（選配）

腳本 repo 附一份 Claude Code skill，可以讓 AI 幫你偵測 library 路徑、跑腳本、核對每一關的數字。
它會照本手冊的九個步驟走，每一關數字不對就停下來，不會硬往前衝。

> ⚠️ **需要付費的 Claude 訂閱（Pro/Max）或 API 計費，約 US$20/月。**
> **沒有也完全沒關係**——本手冊的每一步都設計成可以自己走完，AI 只是加速，不是必要條件。
> 尤其路徑 B 完全不需要 AI，也不需要 Python。

## 用法：三個步驟

**1. 下載 repo 到本機**（見第 4-0 章 ②，zip 或 git clone 都行）

**2. 在「那個資料夾裡面」啟動 AI**

在檔案總管開啟 repo 資料夾 → 網址列打 `powershell` 按 Enter → 輸入 `claude` 或 `codex`。

> 🔴 **一定要在 repo 資料夾裡面啟動**，AI 才讀得到指示檔。在別的地方啟動它不會知道要照這套流程走。

| 工具 | 自動讀哪個檔 | 要設定嗎 |
|---|---|---|
| **Claude Code** | `.claude\skills\endnote-to-zotero\SKILL.md` | 不用 |
| **Codex** | `AGENTS.md` | 不用 |
| 其他 AI | 手動把 `AGENTS.md` 內容貼給它 | 要 |

**3. 貼上開場指令**

## 可以直接複製的指令

**開場**（數字換成你自己的）：

```
我要把 EndNote 搬到 Zotero，請照這個 repo 的流程帶我走。
我的 EndNote 大概 2000 筆、100 個分組左右，作業系統是 Windows。
我不太會用命令列，請一步一步來，每一步等我回報再往下。
```

它會**先問你有沒有正在寫的 Word 論文稿**（就是第 0-1 章那題），再一步步帶你走。

**卡住時**——把畫面上的實際訊息貼給它：

```
我卡在驗證那步，跑出來是 missing: 1952，這是什麼意思？要怎麼修？
```

**看不懂時**——隨時可以問，不要硬做：

```
你剛剛那步在做什麼？為什麼要先關掉 Zotero？
```

**中斷後回來**：

```
我昨天做到匯入完成，snapshot.json 和 plan.json 都還在，接下來要做什麼？
```

**想確認它有沒有亂來**：

```
你接下來這步會動到我的 EndNote 原檔嗎？
```

（正確答案永遠是「不會」——整套流程對 EndNote 都是唯讀。）

## 用 AI 的三個提醒

1. **AI 也會出錯。** 它每一步都會請你確認——**看不懂就問「這步在做什麼」，
   不要因為是 AI 說的就直接按下去。你的文獻庫，你有最終決定權。**
2. **它不會碰你的 EndNote 原庫。** 腳本對 EndNote 是資料庫層強制唯讀，就算 AI 想寫也寫不進去。
3. **數字不對它應該要停。** 如果它在數字對不上時還說「沒關係我們繼續」，
   **那是錯的，請它停下來重查**——這幾關就是用來擋住白做一輪的。
